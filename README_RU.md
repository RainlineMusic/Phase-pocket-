# Phase Pocket 0.1.0 — JUCE prototype

Отдельный плагин Rainline Music на основе Duck Pocket, ветка
`feature/duck-license-sidechain`, commit
`a22697d61485cda9d4a3fcca868e3fb01d03a059` — последний успешный запуск
Actions на момент чтения репозитория. Исследовательское ТЗ приложено в
`Docs/Research_RU.md`.

## Открыть и собрать

- `PhasePocket.jucer` — проект для Projucer, Xcode и Visual Studio 2022.
  Открыть в Projucer JUCE 8.0.6, указать путь к модулям JUCE, сохранить
  проект и открыть выбранную IDE. Для Xcode выбрать Universal binary.
- `CMakeLists.txt` — основная, проверенная конфигурация. Если `JUCE_DIR`
  не задан и соседнего каталога `JUCE` нет, скачивается JUCE 8.0.6.
- `.github/workflows/build.yml` — адаптированный Actions из Duck Pocket:
  macOS Universal VST3/AAX/AU/CLAP и Windows x64 VST3/AAX/CLAP,
  DSP/processor/UI тесты, pluginval, подпись Apple и архивы.
  Этот workflow ещё не запускался на GitHub для нового проекта.

Пример локальной сборки:

```sh
cmake -S . -B build -DJUCE_DIR=/absolute/path/to/JUCE -DPHASE_ENABLE_CLAP=ON
cmake --build build --config Release --target PhasePocket_VST3 PhasePocket_AAX
```

Для macOS Universal добавить при конфигурации:
`-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64" -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0`.

AAX в архиве Actions является developer build. Производственная PACE-подпись
и Apple notarization выполняются отдельно, как для Duck Pocket. Секреты Apple:
`MACOS_CERTIFICATE`, `MACOS_CERTIFICATE_PASSWORD`, `MACOS_SIGNING_IDENTITY`,
опционально `MACOS_KEYCHAIN_PASSWORD`.

Тесты чистого DSP без JUCE:

```sh
cmake -S . -B build-dsp -DPHASE_DSP_ONLY=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-dsp
ctest --test-dir build-dsp --output-on-failure
```

GUI integration tests требуют графическую сессию; в Linux — Xvfb.
Тестовый executable `PhaseIntegrationTests [папка-скриншотов]` проверяет
processor/state и сохраняет реальные снимки интерфейса. Он рассчитан на
прототип с отключённой коммерческой активацией.

## Управление

| Элемент | Значение |
|---|---|
| Threshold | −12…0 dBTP, по умолчанию −1.0; условие запуска и принятия в Strict |
| Max Phase | 0…90°, максимальный модуль общего угла L/R; 0 даёт dry |
| Transition | 5…25 ms, плавное окно входа/выхода; по умолчанию 15 ms |
| Tolerance | 0.02…0.30 dB, допуск изменения RMS/энергии L/R/M/S; по умолчанию 0.10 dB. Он также масштабирует спектральные и временные допуски |
| Acceptance → Strict | По умолчанию. Применить только при достижении Threshold − 0.1 dB и улучшении ≥0.2 dB |
| Acceptance → Partial | Разрешить улучшение ≥0.2 dB без достижения порога; остальные проверки сохраняются |
| Quality | 4x либо 8x оценка реконструированных пиков; 8x по умолчанию |
| Graph window | 0.5 / 1 / 2 / 5 / 10 s; по умолчанию 5 s |
| Theme | Solid Dark, Neon, Amber; палитры и материалы Duck Pocket |
| Freeze | Замораживает только изображение, обработка продолжается |
| Bypass | Задержанный dry; принятый участок завершается своим проверенным fade |

График — верхние 12 dB, вход/выход показываются одновременно. Красные
отметки сверху означают sample peaks выше 0 dBFS. Линия SAVED показывает
снижение максимального реконструированного пика **целого 80-ms участка**;
это не gain reduction. У текущего sample амплитуда после фазовращения
может быть больше исходной, хотя максимум проверенного участка меньше.
IN/OUT — измерения всего последнего оценённого участка с guards, а не
стандартный бесконечный peak hold. У непросчитанного Late участка эти
показания отсутствуют. Angle — выбранный угол на плато; внутри перехода
используется dry/wet окно.

## Как работает первая версия

1. Поток делится на неперекрывающиеся 80-ms участки, каждый с FIR-контекстом
   до/после и запасом для интерполяции. Близкие пики внутри участка
   оптимизируются одним углом. Сложный пик на границе может быть пропущен.
2. Рабочий поток считает FIR Hilbert: нечётное антисимметричное ядро
   `2/(πk)`, Kaiser β=8.6, полная поддержка около 20 ms. FFT используется
   для **линейной FIR-свёртки с zero padding**, не для независимого
   поворота фаз FFT-фреймов. DC и оценённая Nyquist-составляющая отдельно
   сохраняются в in-phase ветви.
3. Полный кандидат: `y = x + w [(cosθ−1)(x−DC−Nyquist) − sinθ H{x}]`.
   Одно окно и один θ применяются к L/R. `w=sin²(πu/2)` на переходах,
   на плато `w=1`. С обоих краёв оставляется точный dry запас ≥56 samples.
4. Перебираются углы с шагом 5°, затем ±4° около лучшего с шагом 1°.
   Вариант без обработки всегда остаётся исходным выбором. На неудаче
   не включается ни лимитер, ни attenuation, ни автогейн.
5. Проверяются float-выход вместе с переходами, реконструированный пик
   обоих каналов, RMS, энергия L/R/M/S, корреляция, центроид энергии,
   энергия до/вокруг/после главного транзиента и 18 спектральных полос.
   Стартовые допуски при Tolerance=0.10: RMS/компоненты 0.1 dB,
   спектральные полосы 0.6 dB, Δcorrelation 0.02, центроид 0.5 ms.
   Пустые полосы/компоненты проверяются отдельно на появление энергии.
6. Аудиопоток получает immutable результат через ограниченную SPSC-очередь.
   Участок фиксируется **до первого выходного sample** и не заменяется
   посередине. При опоздании или конфликте настроек — весь участок dry.

Вызов обработки не выделяет память, не захватывает mutex и не запускает
поиск. Копия snapshot в заранее выделенную очередь выполняется один раз
на 80 ms. При offline render разрешено ждать рабочего потока: так bounce
не зависит от скорости расчёта. При realtime опоздания считаются в Late;
при перегрузке realtime и offline могут дать разный результат, так как
realtime обязан пропустить непросчитанный участок.

Фиксированная PDC: `80 ms + 2 × guard + 120 ms worker budget`, примерно
**224.67 ms при 48 kHz** (10784 samples). При другой частоте меняется число
samples, длительность почти та же. В меню показано фактическое значение.
PDC не меняется при выборе качества, темы, порога или bypass.
Lookahead/контекст первой версии фиксированы; быстрого low-latency режима
нет. Это плагин для мастеринга/обработки, не для мониторинга при записи.

При доступной sample-позиции host playhead скачок позиции (seek/loop) или
смена play/stop сбрасывают delay и очередь планов через generation token.
История графика остаётся монотонной. При отсутствии host timestamp
плагин полагается на вызов `reset()` со стороны хоста.

Настройки принимаются для следующих ещё не выведенных участков. Уже
начавшийся принятый участок заканчивается целиком, максимум через 80 ms;
это относится и к host bypass. Такой порядок сохраняет проверенную форму
перехода вместо внезапного разрыва фазового сигнала.

## Наследование Duck Pocket

Сохранены: исходные Inter, raster dial bodies, кольца и их caches, темы,
геометрия кнопок, меню, resize/aspect ratio, preferences, VBlank pacing,
ограничения графика по числу колонок и по FPS, SPSC telemetry,
неподвижный chrome cache, отдельные repaint-области, плавный display clock,
кэш Direct2D, OpenGL fallback (по умолчанию OFF), размытие BYPASSED,
карточка Online/Offline activation, Apple signing и схема упаковки Actions.

Изменены назначение, plugin IDs, название, график и параметры DSP.
Sidechain-фильтр, M/S balance, Mix/Output gain, ducker envelope и звук утки
не входят в новый тракт: они не соответствуют фазовой оптимизации.

## Активация нового продукта

По умолчанию `PHASE_ENABLE_LICENSING=OFF`: это рабочая тестовая версия,
не требующая ключа Duck Pocket. Система и интерфейс активации сохранены;
пространство продукта изменено на `phase-pocket`, `PhasePocket`, `PHAS`,
`PP2`, `.phaselicense`, отдельные локальные preferences/cache paths.
Нет обращений к API Duck Pocket и нет потребления его лицензий.

Перед включением коммерческой активации необходимо зарегистрировать
Phase Pocket на сервере, подготовить ключи/подпись для нового продукта,
обновить `Source/LicensePublicKey.h` и задать `PHASE_LICENSE_API_URL`.
В CMake включить `PHASE_ENABLE_LICENSING=ON`; для Projucer изменить
соответствующий define и `Config/LicenseConfig.h`. Проверка всей цепочки
активации нового серверного продукта пока не проводилась.

Детальные результаты локальной проверки: `Docs/VALIDATION_RU.md`.

## Ограничения исследования

Это реализация варианта A из ТЗ. Нет патентной synced-allpass схемы,
allpass/chirp банка B или произвольной FFT phase optimization D.
Полностью адаптивное объединение событий через границы 80-ms участков
пока не реализовано: текущая версия консервативно пропускает такие случаи.

FIR Hilbert и реконструкция пиков конечны. 4x/8x Kaiser sinc — модель,
не заявление о сертификации измерителя по ITU-R BS.1770. Запас 0.1 dB
и независимые 16x тесты снижают риск, но не являются математической
гарантией непрерывного пика для произвольного входа.

Условный Threshold не является ceiling. Неподходящие пики остаются выше
порога. Цифры синтетических тестов не характеризуют среднее улучшение
на музыке. Изменение фазы не даёт нулевой difference/null при принятой
обработке. Нужны уровненные A/B, ABX, проверки тональности, pre/post-ringing,
плотных миксов и реальных DAW, прежде чем заявлять прозрачность или релиз.
