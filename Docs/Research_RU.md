# Selective Phase Peak Optimizer — исследование и техническая спецификация

Дата: 16.10.2026. Цель: VST3/AAX аудиоплагин для предварительного мастеринга, который **селективно** уменьшает пики изменением фазы, без обычного изменения gain. Вариант, который не достигает заданного результата либо не проходит проверки, не применяется.

## 2. Целевая функция

Пусть x_c[n] — вход (c ∈ {L,R}), fs — sample rate, T=10^(Threshold_dBFS/20) — линейный порог. Сначала рассчитывается истинный пик P_TP с помощью качественной интерполяции (например, 4x/8x). Для каждого события E, где P_TP(x,E)>T, рассматривается набор **полных** кандидатов: сухой и обработанные с учётом переходов, памяти фильтров и хвостов.

Жёсткое правило применения для STRICT-режима:

accept(y,E) ⇔ P_TP(y,E_ext) ≤ T−M AND P_TP(y,E_ext) ≤ P_TP(x,E_ext)−δ AND artifact_checks(y,x,E_ext)=PASS.

E_ext — расширенный контекст события (attack, release, lookahead, фильтровый хвост). M — запас на ISP и интерполяционную ошибку; δ — минимально значимое улучшение. Если не удалось опустить ниже T, **сохранять dry**, а не превращаться в ограничитель. Если пик исходно ниже порога, ничего не делать. Порог в этом алгоритме НЕ является безусловным output ceiling: невозможные события останутся выше него.

В альтернативном режиме PARTIAL можно принимать улучшение без полного достижения T, но не следует включать этот режим по умолчанию.

## 3. Схема A — аналитический сигнал и постоянный угол на событие

Для вещественного нуль-среднего x:

H{x}(t) ↔ −j sgn(ω) X(ω).

z(t)=x(t)+j H{x}(t),

y_θ(t)=Re(z(t)e^{jθ})=x(t)cosθ−H{x}(t)sinθ.

Постоянный θ — идеальный LTI allpass по амплитудному спектру: Y(ω)=X(ω)e^{jθ sgn(ω)} при ω ≠ 0 (знак определяется соглашением об оси); |Y(ω)|=|X(ω)|. В полной математической постановке DC (а также специальный бин Nyquist в дискретной реализации) обрабатываются отдельно: нельзя молча приписывать общую фазу обоим знакам частоты в точке, где они совпадают.

Для многоканального аудио использовать **один и тот же θ(t)** на обоих каналах. В вычислении учитывать максимумы L, R и TP реконструкции.

Поставим I_c[n]=x_c[n−D], Q_c[n]=Hilbert_c[n] с совпадающей задержкой D. Оптимизация одного θ на расширенном окне:

θ* = argmin_θ max_{c,n∈E_ext} |I_c[n]cosθ−Q_c[n]sinθ|.

Без переходов это одномерная min–max задача. Старт: включить θ=0; грубый поиск по θ от −90° до +90° с шагом 2–5° (более широкий диапазон возможен, но 180° меняет полярность); локальная донастройка лучшего угла через bounded scalar minimization. Важно: не минимизировать только один sample пика: новый максимум может появиться поблизости или в другом канале.

Производная:

∂y_θ[n]/∂θ = −I[n]sinθ−Q[n]cosθ.

При гладкой замене max на log-sum-exp можно использовать градиентные методы; прямой грубый 1D поиск в real-time чаще дешевле и надёжнее.

### FIR Hilbert

Идеальное дискретное ядро h[k] = 2/(πk) для k нечётных, h[k]=0 для k чётных и k=0. Оконечить симметричным окном (например, Kaiser), использовать нечётную длину N, групповая задержка D=(N−1)/2. I должен быть задержан ровно на D. Погрешности на DC, Nyquist и краях полосы учитывать в замере пиков.

Альтернатива: FFT-построение аналитического сигнала при корректной OLA/overlap-save с достаточными guard-областями. Простое FFT всего отрезка с независимыми границами вызовет circular wrap/краевые выбросы.

### Самая серьёзная проблема — включение/выключение

Если y[n] = x[n]cosθ[n]−q[n]sinθ[n], а θ[n] меняется, это уже **не тот же LTI allpass**. Происходит частотная модуляция/появляются боковые полосы, возможны слышимые артефакты. Нельзя утверждать «спектр не меняется» для такой локальной схемы. На практике гораздо безопаснее применять **один постоянный θ в середине события**, а в ненапряжённых местах перед событием и после него плавно возвращаться к нулю.

Для dry/wet оконного смешивания:

y[n] = x[n] + w[n] (I[n]cosθ − Q[n]sinθ − x[n]), 0≤w[n]≤1.

При w=0 выход строго равен выровненному по задержке исходнику. При w=1 выход соответствует повернутому сигналу. При 0<w<1 операция **не allpass**, может частотно окрашивать; результат обязательно проверять по спектру, TP и переходным артефактам.

Плавный переход w(u)=sin²(πu/2), u∈[0,1], имеет нулевой наклон на концах. Выбор 10–20ms в качестве стартовой настройки fade, затем измерения. Переход не должен совпадать с сильным транзиентом. Альтернативно сглаживать θ(t) напрямую и сравнить на тестах.

Один переход на близлежащие пики лучше раздельных переходов. Если новые пики появляются внутри fade или после него, отклонить кандидата и вернуть dry.

## 4. Схема B — Schroeder allpass: полностью выписанная математика

Одна секция:

H_{m,g}(z)=(g+z^{-m})/(1+g z^{-m}),    |g|<1, m∈ℕ,

y[n]=g x[n]+x[n−m]−g y[n−m].

При фиксированных m,g модуль частотного отклика равен 1 (allpass). Для дельта-импульса:

h[0]=g,
h[m]=1−g²,
h[km]=(1−g²)(−g)^{k−1} при k≥1,
h[n]=0 в остальных точках.

Для 0≤g<1 максимальная амплитуда импульсной характеристики равна max(g,1−g²). Минимум максимума достигается при g=1−g², следовательно:

g* = (√5−1)/2 ≈ 0.618034.

При таком g максимальный sample импульса ≈0.618 вместо исходного 1, что соответствует 20log10(0.618)=−4.18 dB. Этот результат относится к идеализированному одиночному импульсу, а не гарантируется на музыке. При каждом m появляются хвостовые импульсы на расстояниях m, 2m, 3m ...; чем больше m и |g|, тем длиннее temporal smearing.

Три секции в каскаде:

H_total(z)=∏_{k=1}^3 (g_k+z^{−m_k})/(1+g_k z^{−m_k}).

Исторический базовый набор 2013/2014: g≈[−0.618, +0.618, −0.618]; искать m_k∈[1,30] при 44.1 kHz (это не строгий универсальный предел при других sample rates). Проверять (включая без обработки) фактический пиковый уровень каждого кандидата. Это математически конкретный, но дорогой для полного поиска подход.

ВНИМАНИЕ: если включать/выключать IIR allpass, его внутреннее состояние и хвост не должны обнуляться в середине звука. Нужны постоянно работающие подготовленные ветви или корректная модель pre-roll/tail и плавный transition. Обходы кандидатов должны оцениваться с теми же state/transition, которые реально будут при воспроизведении.

## 5. Схема C — автокорреляция и производная (связана с действующим патентом)

Из работы ICASSP 2022 и формул патента US11881829B2:

R_xx[m]=∑_n x[n]x[n−m].

Вместо грубого перебора m находят наиболее выраженные положительные и отрицательные экстремумы R_xx[m], затем для каждого m оптимизируют g. Физический смысл: удачный m связывает противофазные колебания, что может снизить транзиентный пик. Сам патент описывает конкретный выбор m по двум важным отрицательным и двум положительным экстремумам, и особый способ оптимизации g. Не переносить эту запатентованную комбинацию в коммерческий продукт без FTO-анализа.

Общий критерий:

(m*,g*) = argmin_{m,g} P_{m,g},   P_{m,g}=max_n |y_{m,g}[n]|.

Производная передаточной функции по g:

∂H/∂g = (1−z^{-2m})/(1+g z^{-m})².

Можно реализовать рекурсию градиента u[n]=∂y[n]/∂g:

u[n] = x[n]−y[n−m]−g u[n−m].

Линеаризованное обновление:

y_{g+γ}[n] ≈ y_g[n]+γ u[n].

Минимизировать t при линейных ограничениях для каждого n:

−t ≤ y_g[n]+γu[n] ≤ t.

Это 2-variable linear program (γ,t) при ограничении допустимого диапазона |g+γ|<1. Затем пересчитывать **точный** поток с новым g и сравнивать TP; линеаризация сама не гарантирует улучшение.

## 6. Схема D — фазовая оптимизация FFT / alternating projections (экспериментально)

Для фрейма X[k]=FFT(x[n]) сохранять модуль |X[k]| и оптимизировать фазу φ[k], чтобы минимизировать max|IFFT(|X|exp(jφ))|. Для вещественного выхода соблюдать сопряжённую симметрию; запретить произвольные фазы для DC/Nyquist. Вариант projected iterative clip+restore magnitude: (1) ограничить пики во времени; (2) FFT; (3) заменить новые модули старым |X|, сохранить фазы; (4) IFFT; (5) повторять, оценивая TP и качество. Это **не эквивалент** единому фазовому сдвигу всего диапазона; легко разрушить временную структуру атаки и создать pre-echo. Для первой версии не рекомендуется. FFT-кандидаты необходимо оценивать на перекрывающихся блоках, а не на отдельных изолированных отрезках.

## 7. Объективные проверки безопасности

- **Peak & true peak** на всём E_ext после всех переходов: TP_out ≤ TP_in и в STRICT TP_out ≤ T−M. Internal evaluation 4x/8x с качественным анти-имиджингом, для тестов — отдельный измеритель, например ITU-R BS.1770-compatible true-peak oversampling. Проверять каналы отдельно и стереосуммы при релевантном контроле.
- **No-op invariant**: весь вход строго ниже T ⇒ битово/численно совпадающий с исходником задержанный выход; θ=0, w=0 должны быть точным bypass, не проходить через неточный allpass.
- **Side effects / transitions**: повторное сканирование E_ext после применения всех обработок, включая тылы фильтра и границы окон; соседние события агрегируются.
- **Loudness/RMS preservation**: LTI allpass сохраняет интегральную энергию бесконечного сигнала; в ограниченном окне и при переменном θ это уже не тождество. Ограничить |ΔRMS| / |Δshort-term loudness|, например предварительный эвристический порог 0.1 dB, проверять слухом.
- **Spectral coloration**: интегральный и многополосный модуль FFT/STFT и лог-спектральная ошибка. Порог зависит от частоты/материала, должен калиброваться, не считать спектральную метрику доказательством неслышимости.
- **Stereo stability**: одинаковый θ(t), m/g и w(t) для L/R; контролировать ΔM/S balance, interchannel coherence/correlation и TP обоих каналов. При асимметрии по каналам переход по индивидуальным параметрам может деформировать сцену.
- **Transient temporal integrity**: сравнить локальное центроидное время энергии / максимум cross-correlation, атаку (например, окна 0–5ms, 5–20ms), частотные хвосты, pre-ringing. Избежать заметного запаздывания и расширения атаки.
- **Null/difference listening**: не обещать беззвучный null при фазовом вращении. Нулевой тест для allpass не валидирует прозрачность; использовать уровненные A/B и ABX, наушники/мониторы, разные уровни громкости.
- **NaN/Inf/denormals, silence, DC, polarity, Nyquist, parameter automation, host block-size changes**: строгие юнит-тесты и rate-specific настройки.

Прохождение проверок гарантирует только соблюдение **заданных измеримых ограничений**, а не субъективное «звук не изменился».

## 8. Реальное время / lookahead

Lookahead нужен, чтобы заранее определить будущую локальную структуру и закончить phase transition до главного транзиента. Минимальную задержку определяют одновременно FIR Hilbert group delay, размер анализа будущего контекста, начальные/конечные fade, tail allpass и TP-измерение. В offline-render возможен глобальный двухпроходный анализ без ограничения на real-time latency.

Экспериментальные стартовые параметры для первой JUCE-версии: lookahead 60–100 ms (например, 80 ms); окно оценки события ~40–100 ms плюс guards; fade 10–20 ms на незагруженных участках; варианты θ от −90° до +90° с шагом 5° и локальной донастройкой; accepted improvement ≥0.2 dB, safety margin TP ≈0.1 dB. ЭТО НЕ опубликованные «оптимальные» числа, а консервативные начальные гипотезы для тестирования. При 48k 4096 samples = 85.33 ms. Оценку обработанного кандидата делать в отдельном preallocated worker/ring buffer с жёстким ограничением CPU; не выделять память и не запускать тяжёлый поиск в audio callback.

Поддерживать PDC и одинаковую задержку в bypass. При изменении fs, block size, plugin prepareToPlay — пересоздание буферов вне real-time. Не менять параметры IIR резко: риск нестабильного состояния и артефактов.

## 9. Event scheduling / алгоритм первой версии

```
input: stereo x[n], fs, threshold T, configured L
output: y[n] = delayed x[n] unless a SAFE event plan is accepted

1. Maintain delayed dry ring buffer and lookahead analysis buffer.
2. Detect candidate excursions using reconstructed true-peak oversampled signal.
3. Merge close excursions; extend region with pre-roll, post-roll, transition, Hilbert/ allpass support.
4. If event has no safe transition space, output dry and mark skipped.
5. Compute I_L, Q_L, I_R, Q_R with properly aligned analytic-signal generator.
6. Candidate[0] = exact dry (theta = 0).
7. For every trial theta: synthesize complete event INCLUDING fade-in/out; verify both channels over whole extended region; compute TP; collect penalties (spectral/stereo/transient).
8. Choose candidate that satisfies all guards AND reaches T−margin (STRICT).
9. If no candidate, emit delayed dry exactly. If yes, schedule same theta and same transition for both channels.
10. Re-evaluate after overlapping scheduled events and reject conflicting plans.
11. Maintain fixed PDC and a debug telemetry channel for peak_in/out, accepted/skipped, angle, quality scores.
```

**Сложная часть:** 5–20ms fade вокруг непериодической атаки сам может быть слышим, даже если фаза на плато неслышима. Поэтому нужно экспериментально сравнить (A) Hilbert event-aware, (B) статический фазовращатель целого фрейма, (C) allpass short chirp кандидаты. Вполне возможно, что селективный подход окажется хуже по субъективной прозрачности, чем **фиксированный угол на большой секции**. Это гипотеза для проверки, а не маркетинговое обещание.

## 10. Предлагаемый пользовательский интерфейс

Для начала один главный элемент **Threshold (dBFS или dBTP)**; в меню — режим **Strict / Partial** (Strict по умолчанию), **Lookahead** (например, 40/80/120ms) и **Quality**. Отображение входного/выходного true-peak, сэкономленных dB, числа безопасно обработанных / пропущенных событий. Без Input Gain, Output Gain, Attack, Release, Mix по умолчанию. Если порог в dBTP — сигнал выше порога может остаться выше после плагина, и об этом нужно явно писать в интерфейсе: «reduction is conditional, not a limiter».

## 11. План валидации

A. Искусственные тесты: один impulse; 40Hz и 100Hz синусы; асимметричные harmonic stacks; pair of close transients; ступенчатая смена синуса; L=R; L=−R; L-only; DC offset; near Nyquist.

B. Музыка: kick+bass, 808, барабанные bus, вокал с асимметрией, пианино, оркестр, плотный готовый микс; разные fs 44.1/48/96/192 kHz.

C. Metrics per file: Δsample-peak, Δtrue-peak, ΔRMS, ΔLUFS, ΔM/S energy, max local spectral change, transition artifact count, CPU usage, accepted rate.

D. Blind ABX и контрольная группа: fixed Hilbert θ, baseline allpass, event-aware, bypass; loudness-match. Для готового микса сравнивать не просто снижение пика, а *сколько дополнительной громкости даёт последующий одинаковый лимитер при том же субъективном качестве*.

E. Stress JUCE/DAWs: offline render vs realtime deterministic results, host block 1/16/64/512/4096, bypass toggle, seek/transport stop, sample-rate switch, bounced sample-accurate alignment.

## 12. Рекомендуемый порядок разработки

**MVP 1**: отключённая/ручная обработка: доказать исправность Hilbert FIR, угол θ, измерение TP и автоматический global-angle optimizer на целом треке. Затем сравнить с RX Suggest/x42.

**MVP 2**: selective lookahead optimizer с детекцией по Threshold, theta-search, мягкими переходами, обязательным dry кандидатом и строгим TP gate. В первую очередь тестировать **выполненность ограничений и артефакты**.

**MVP 3**: добавить независимый short allpass / chirp поиск, сравнить с Hilbert. К патентной реализации SyncAPF не переходить без FTO.

Вывод: нет универсального решения для каждого превышения Threshold при чисто фазовой обработке. Для ряда сигналов, например продолжительного синуса или насыщенного ограниченного микса, уменьшение максимума безопасным фазовым преобразованием может быть нулевым. Критерий качества и bypass — не второстепенная опция, а сама сущность продукта.
